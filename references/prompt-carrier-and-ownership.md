# FactoryWeaver v7.2 — Prompt Carrier and Deterministic Handoff Contract

**Goal:** Preserve the user's true outcome, technical source, constraints and original effects across the transformations from AGENTS.md → v7.2 instructions → Card → Scope → Prompt Delta → Soodles Reader → original Session → admitted Noodle stage → conditional Managers → provider readback. This is a **semantic process reference**, not a new JSON protocol or an API System-role grant.

## Card-generation feedback → Session-composed instruction

There are **two distinct semantic delta boundaries** in the existing carriers;
do not share a mutable state field or create another scheduler/schema.

1. **Before/during Card compilation**, current Session's source-grounded
   generation feedback names an unsupported premise, mistaken Consumer I/O,
   irrelevant edge or missing discriminating control. Update only the original
   affected Card/typed-link producer and its ordinary revision after independent
   source review. A Card acceptance cannot be "fixed" by changing only a later
   worker instruction. No material change means REUSE/NOOP.
2. **After Card acceptance**, an R Roadmap may suggest causal units and existing
   Card links. Original CLI may enumerate these references read-only. Current
   Session compares fresh Goal, Original Owner next, actual failure and affected
   Consumers; chooses an evidence-supported minimal sufficient Scope, even if
   the R is missing or outdated; then composes a consumer-specific One-Shot
   Prompt. It does not concatenate cards: preserve required behavior, covered
   parent clauses, inputs, invariants, negative cases, independent oracle,
   stop/readback and Worker implementation freedom. `PromptDelta` in the
   existing Scope Bundle means only *new material worker behavior*, or NOOP.

Model-authored prompt composition is probabilistic; a CLI cannot certify it
as semantically optimal. Existing `factoryweaver/v1` cards and
`factoryweaver/soodles-scope/v1` selection retain their unchanged protocols.
Original `card_semantic.py roadmap` validates and projects existing card IDs/
R links, not missing semantic dependencies. Original Soodles Issue Contract
reconciles proposed Goal with the actual task. The Stage only consumes the
instruction after original admission. Prompt construction neither grants
runtime permission nor proves actual Agent compliance.

**Discriminators:** (a) an R index with no selected Scope cannot trigger an
Issue or Stage, (b) omitting an applicable G must fail independent semantic
review even if its schema is valid, (c) current local Parser PASS cannot close
replay/training Parent REQ, (d) unchanged owner next leads to NOOP, (e) a new
runtime digest/argv in model text is not accepted producer truth. Preserve
historical and current evidence separately.

## Always classify reasoning mistakes at the **first changed carrier**

For a material handoff, the supervising Session checks (a) original goal/condition/source, (b) current carrier content and actual Consumer, (c) one source-backed counterexample, (d) which **original Producer** can resolve the first uncertain value, and (e) whether returned `next` already fixes the path. Correct the **single earliest incorrect premise/duplicate decision**, not every later prompt independently. If the scope has no observed barrier, NOOP; avoid a reflexive Thinking Router.

Invalid examples: a syllabus heading becomes a C mechanism; REGISTRY ID proves duplicated Goal is equal; a selected `pstack architect` mention proves invocation; a card `validated_by V` claims the V was run; Hook/Cron are launched because G/P/V mentions them; `consumer_report` PASS becomes real provider delivery; a wrong `next.argv` is hand-reconstructed from an operation label.

## Actor, trust and verification

- **Session:** semantic judge of Goal, causal Scope and genuine tradeoff; responsible for preparing authorized original Issue, not a free-standing grant of effect.
- **P-class:** conditional instructions executed by a probabilistic Agent. It is not itself a probabilistic transition engine. **Reading an instruction does not establish the Agent followed it**.
- **CLI / original Owner:** deterministic state machine over actual selected input/identity/authority; only original owner/provider can certify an external effect.
- **Knowledge Cards:** technical evidence and reusable source-backed constraints, not executable directives. Material Prompt Delta survives only into the original admitted Stage after readback, not as a new independent System Prompt.
- **Runtime metadata:** keep real Consumer-needed IDs/heads/digests/argv **only in Host/Original Producer receipts**. Never ask the model to compute, copy or invent them; use returned `materialization.next` or `reader_arguments` exactly. Do not create new scheduler/cursor/retry/telemetry fields for documentation.

**Three-layer proof:** (1) source-independent Card semantic verification beyond machine shape, (2) real Reader/CLI invocation and typed refusal, (3) fresh native P-class consumer plus original Outer/Inner/necessary Manager/Provider receipts. Each incomplete layer remains NOT_RUN/UNVERIFIED, not a universal PASS.

## Repeated pstack maintain verification

The pinned original `create-verification-skill` made the project-local `verify-factoryweaver` once. On real source/behavior/feature drift, `maintain-verification-skill` source-reviews **every** mapped feature with actual source cited and independent read-only Agent reasoning where available, reconciles the index, then drives each reachable user path using the current Harness and retains logs. `maintain --scope local` is local CLI-only. `maintain --scope full` remains blocked without original native carriers and independent Source truth. A Product Bug goes to its original Owner; within maintain edit only the verification skill directory, re-drive, and at most one PR for proven corrections. Soodles `verify-soodles` retains its separate original native 21-feature map and canonical admission boundaries. Neither uses source-path existence or prompt-text inspection to claim Agent adherence.
