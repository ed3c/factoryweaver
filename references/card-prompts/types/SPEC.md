# SPEC — Selected Card Generation Contract

**Trigger:** Observable implementation behavior has a testable boundary.

**Input:** Host-observed source assertions and source coverage, current user Goal, previously accepted matching cards, applicable original owner/constraints. Never invent source pages, digests, commit IDs, execution IDs, timestamps, cursors, measurements, or tool argv. If evidence is unavailable, return a named K or NOOP rather than guessing.

**Generate only this epistemic role:** Define state, caller/consumer, typed I/O and refusals; no implementation recipe unless requirement fixes algorithm.

**Required semantic slots (use type-specific meaning, not boilerplate):**
- **given** — source-backed and concrete; describe what changes in the engineering decision where applicable.
- **when** — source-backed and concrete; describe what changes in the engineering decision where applicable.
- **then** — state the observable result of this Consumer; do not claim a later Runner, native Consumer or Provider result from a proposal output.
- **inputs_outputs** — name the Producer, Consumer, required input types/references and output variants at this same boundary; define aliases instead of making the Consumer guess them.
- **forbidden** — source-backed and concrete; describe what changes in the engineering decision where applicable.
- **negative_case** — source-backed and concrete; describe what changes in the engineering decision where applicable.
- **unknown_effect** — source-backed and concrete; describe what changes in the engineering decision where applicable.
- **replay** — source-backed and concrete; describe what changes in the engineering decision where applicable.
- **oracle** — name the original method/Producer that discriminates this output and refusal boundary; it cannot be the desired result copied as a test method.
- **original_owner** — source-backed and concrete; describe what changes in the engineering decision where applicable.

**Observed API versus opaque references:** When actual source code exists,
name the *real* public API input variants and types, including which fields
are opaque Producer references rather than loaded objects. Do not infer file
dereference, Runner execution, authorization or a full parent outcome merely
from a reference name. Example: a parser consuming raw bytes plus Owner-fixed
mapping may return parsed data/refusal without reading TaskSnapshot content.
Keep local `then`, I/O and oracle bounded to that same Consumer.
**Scope contribution:** One causal implementation atom with required controls and owner.

**Rejection/non-case:** Generic 'implement as required' or no oracle; do not assert tested.

**Conditional Soodles Outer Loop:** issue-atom and Test Manager, original effect owner. Select only after actual evidence and valid owner next are checked; mapping does not itself invoke a skill.

**Conditional Noodle Poteto/pstack:** pstack architect/tdd only if chosen by admitted poteto-mode. Worker follows the already admitted playbook and has implementation freedom within its fixed contract.

**Review-writing:** Check actor, condition before required action, evidence and causal direction, proposed vs observed state, acceptance/unknown, exact technical terms, and preservation of original goal. Apply only this card's meaningful slots; do not require a `K` card to know an unavailable mechanism. Only a real P-class instruction edit triggers scoped behavior evals.

**Output:** semantic CREATE/UPDATE/REUSE/NOOP proposal, source-grounded field content, typed links with direction/counterfactual, and relevant continuation obligation. The original Host resolves stable identity and version. A valid shape is not a semantic PASS.
