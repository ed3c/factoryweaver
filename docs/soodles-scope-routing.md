The [Migration-RL card draft](specifications/migration-rl/README.md) is specification-only. ## Card preflight

Read [v7.2 Card Classification / Scope Assembly](../references/card-classification-and-scope-assembly.md) before selecting cards, links, or Skills. The reference now defines a per-series **Soodles Outer Loop → conditional Noodle Poteto/pstack Skill Consumer matrix**, multimodal input/coverage semantics and `review-writing` zero-context quality gates. These mappings are selectable methods, **not automatic tool calls**. The original 15 series fall into five functional groups; the seven core types C/REQ/G/SPEC/V/X/K are optional per Scope, not a compulsory recipe. Never manufacture four types to fill the four display slots. Reuse applicable C/G and prioritize real source-backed semantic UPDATEs.

The four output contracts ScopeManifest, SkillRoute, PromptDelta, Continuation are semantic sidecars, not a new card series. Every material link must specify its direction, condition and what behavior/test fails if the linked prerequisite changes; a chronological syllabus relationship alone is not a depends_on/enables causal relation. Reject generic lecture-title cards and copied worker prompts; do not misrepresent unread Slides/Readings as verified evidence.
## Dedicated producer → consumer Scope Bundle

FactoryWeaver does **not** send Markdown cards, freeform prompt text or model-computed IDs to Soodles for execution. It exports the original complete `factoryweaver/v1` knowledge record **plus** one selected semantic Scope through the read-only [Scope Bundle contract](factoryweaver-soodles-readback.md). The original Host supplies the selected file and exact computed digest; Soodles' [native `knowledge inspect`](https://github.com/ed3c/soodles/blob/feat/factoryweaver-scope-readback/contracts/factoryweaver-scope-v1.md) consumes it, returns selected REQs/Card payloads and Prompt Delta as *untrusted proposal*, and preserves `next=null` and full remaining REQ inventory. Only the original Soodles Session reconciles the Issue and delegates to `issue-atom` / Test Manager / Noodle. This adds no new scheduler, authority, Hook or replacement validator.

## 1. Compilation unit and invariant

**One Behavior Scope = one *proposed* causal Issue Atom boundary, not one Card.** A Scope can include many reused C / G / REQ / SPEC / V / K / X cards. One original outcome may require **several sequential or dependent Issue Atoms**; never split away its required callers, tests, fixtures, consumers, rollback or landing obligations. Scope membership is a selection of relevant card semantics, not a new effect owner.

Every behavior scope has a **Goal-Oriented Contract** with these semantic fields:

| Field | Meaning | Quality gate |
| --- | --- | --- |
| `goal` | Observable target, direction/threshold or defensible qualitative success condition | User intent, not model-invented target |
| `measurement` | Authoritative measurement producer, calculation definition, sample population/window, exclusions, accepted evidence and evaluator | Code/SQL/Provider when measurable; no imagined metrics |
| `persistence` | What subsequent evidence-driven attempts should happen while goal is unmet; who preserves the original task; allocated or unknown effort horizon | Continuation obligation, not infinite retries/new Issue per attempt |
| `stopping_and_escalation` | Success; blocked prerequisite; re-evaluation after repeated failed correction; scope/budget change requiring original owner or user decision | Local writer complete != higher-level goal achieved |
| `issue_atom` | One causal intervention with affected callers, fixtures, tests, owner, effect boundary, rollback, acceptance and later landing | An atom is bounded even if parent goal takes weeks |
| `evidence_state` | Source fact, measured result, proposal or unknown and where actual result would come from | Cannot report measured PASS using predicted values |

**Example:** Parent goal is *p95 CI duration under 10 minutes*; measurement may be production BigQuery CI-run data only if the real provider has this source. Record precisely what counts as run duration, which workflows and sample period belong to the p95 population, minimum validity criteria and treatment/base comparison. No sample population means `measurement=UNRESOLVED`, not a fabricated p95. An individual atom may remove one observed duplicated build/fixture step and measure its contribution; its writer completion cannot close the parent p95 goal. Follow-up atoms retain the original goal and evidence ledger, not a new untracked task.

A statement such as "keep trying, potentially for weeks" is **persistence policy**, not a promise that a model is executing in background. It requires the original authorized host/session/scheduler to exist for future runs, with actual cost/time/attempt limits or an explicitly unknown budget. Maintain the goal until satisfied or a real blocker is returned; do not endlessly replay failed commands, effects or identical experiments. Respect existing three-failed-corrections causal reassessment and unknown-write readback.

## 2. Strict outer loop / inner loop split

**Soodles outer loop (Session / Issue Atom / original owner):**
- Preserves the whole-task REQ inventory and goal measurements; chooses one bounded behavior scope/atom and selects whether a material reasoning question exists.
- Prepares original Issue Contract through installed `issue-atom`, and selects conditional skills below with source-grounded triggers, verified inputs, expected outputs and stop/return state.
- Chooses evidence/falsifiers and routes objective measurement to provider/CLI/Test Manager. Resolves unclear business goal through Thinking Router and user-decision skill; unclear evaluation through verified Evals skills, if installed. Respects no-op routes.
- Admits and resumes work only through the original effect owner; consumes selected manager next and records original provider readback.
- On candidate readback selects `outer-review` only where a concrete review question exists. Owns subsequent corrective atom, publication, landing, native activation (if required), cumulative goal evaluation and conditional follow-up.

**Noodle Poteto inner loop (admitted `execute` worker):**
- Receives a **bullet list of semantic Prompt Delta requirements**, original requested outcome, acceptance, non-cases, change/effect boundary, and relevant scope card semantics. No fake hashes, paths, cursors, args, provider results or invented workflow identities.
- Uses already selected Poteto playbook once, or lets the installed Poteto mode select one when none was selected. Chooses implementation technique, internal sequencing and local engineering corrections **freely within the admitted contract and real carrier capabilities**.
- Reuses Test Manager's chosen verification, consumes actual results, and reports `completed` / `blocked` / `failed` to original stage owner. Does **not** relaunch or choose the outer skill route, self-expand write paths, spawn extra workers, merge/close PRs, operate Cron/Hook as a new scheduler, or declare parent goal complete.

### Outer-loop Skill Trigger Matrix

| Work / uncertainty observed | Outer-loop Skill route | Expected result | Explicit non-trigger |
| --- | --- | --- | --- |
| Every selected Behavior Scope | `issue-atom` via original Session | One source-bound Issue Contract proposal/admission route | No fresh Issue merely because four slots were rendered |
| Goal already clear and valid Owner next exists | **No Thinking Skill**; follow original next | Existing continuation and evidence | Never repeat `think` or `grilling` |
| New architecture or viability decision, not previously settled | `thinking-router` → `think` | Decision-complete design, alternatives, assumptions, stopping tests | No mandatory planning approval for ordinary admitted fixes |
| Genuine product-goal threshold, tradeoff or acceptance ambiguity | `thinking-router` → installed `grilling`; manual `grill-me` only in supported invocation mode | User-confirmed goal/measurement decision | Never grill for lookup facts or already-answered questions |
| Semantic premise/failure claim needing a falsifier | `thinking-router` → `adversarial-review`; bound Brain A/B if needed | Discriminating counterexample and oracle | Not automatically two models per card |
| Two plausible architecture layouts or unnecessary mechanism | `thinking-router` → `high-cohesion-low-coupling` or `occams-razor`; `think` only when genuinely needed | Simpler scoped design preserving requirements | Does not imply Ponytail global mode |
| Several simultaneous interventions confound effect | `thinking-router` → `ablation`, then `test-manager` | Smallest feasible matched comparison and causal limitations | No automatic full-suite or broad experiment |
| Objective CI/latency/SQL metric defined | Original metric producer + `test-manager` when controls needed | Actual dataset/query and measured baseline/treatment | No LLM judge where deterministic result exists |
| Goal quality ambiguous and **traces exist** | Installed Evals `error-discovery` if available | Observed failure taxonomy and candidate eval cases | Do not invent rubric before error analysis |
| Existing Evals pipeline's evaluator untrusted | Installed `eval-audit`; then `validate-evaluator` where applicable | Audit of failure cases, evaluator validity and quality | Frozen repository examples are not proof skill is installed |
| No traces and LLM Evals really required | Discover installed `evals-start` and permitted downstream capabilities; else K | Explicit evidence/data-collection plan | No fake model, trace or judge |
| P-class guidance changed | `review-writing` + scoped Agent behavior feedback + Schema owner | Semantic fidelity, fresh-consumer observation, owner next | N-class prose-only edits don't demand model eval |
| Specific candidate has review-worthy diff | `outer-review` → Ponytail review and/or Waza Check as evidence requires | Independent findings on exact candidate, original owner resolves | Do not unconditionally run both or install hooks |
| Native Stop/heartbeat condition actually applies | Existing Hook/Cron owners **only through selected carrier** | Native readback, required continuation | No new scheduler or inferred native execution |
| Selected tests or measured costs needed | `test-manager` | Minimal discriminating verification selection, observed results | No routine blanket suite |
| Work admitted and implementation ready | Original `execute` → selected `poteto-mode` | Writer result and later-owner obligations | Outer loop does not micro-manage implementation |

**Skill availability gate:** select from currently supported and installed Host packages. Soodles currently has `think`, `thinking-router`, `grilling`, `test-manager`, `review-writing`, `issue-atom`, `execute`, `outer-review`; its repository also contains historical frozen `evals-start` and `eval-audit` examples, **not** evidence of an installed live Evals capability. If an Evals subskill is absent, return a named dependency and continue unaffected work. No fallback hallucination.

## 3. Thinking and cognitive recursion slots (extensible)

`thinking` is a semantic part of each Scope, **not required invocation**.

- `decision_class`: `none | implementation | architecture | business_goal | evaluation | causal_inference | ownership` (profile suggestions; extensible only via validated host schema).
- `requires_reasoning`: whether a meaningful unresolved decision could alter scope or acceptance. Source/CLI facts are first.
- `think_skill`: only for architecture/value/decision-complete plans when indicated.
- `thinking_method`: selected existing method (first-principles, adversarial-review, ablation, occams-razor, high-cohesion-low-coupling), or `none`.
- `two_brain`: Brain A claim/premise/predicted effect; Brain B strongest falsifier/competing explanation; common **external** evidence or oracle; result supported/refuted/unknown; bounded stop condition. Use no second brain unless discriminating value exists.
- `goal_uncertainty`: `known | requires_user_decision | requires_source | requires_evals | unknown`; selects a **single next responsible route**, not all skills at once.
- `prompt_delta`: the **minimal change in instruction focus** after actual reasoning. Possible `NOOP`.
- `extension_fields`: optional namespaced semantic enhancements (e.g. architecture ADR implication, measure methodology, failure taxonomy, policy applicability). Unrecognized fields are **not** written into legacy v1 contracts; add a separate proposed Sidecar and a real host adapter when necessary.

If user judgment is genuinely required and no established answer exists, `grilling` handles choices; if evaluator quality is unknown, prefer actual traces/error-discovery/audit; if the metric is objectively computable, use the metric owner and Test Manager, not a model-based rubric.

## 4. Four fixed content slots; Boot then Drill-down Patch

For Soodles profile: **exactly four visual slots** for every substantive card batch; actual meaningful CREATE/UPDATE count is at most four, and `UNUSED` terminal slots are only display placeholders. A status-only `NOOP` or `BLOCKED` response does not invent cards. Do not force different card types in each slot.

**Boot:** First extract and store full requirement/source inventory beyond the displayed slots. Then present up to four real high-leverage cards and pending obligations, including Goal + Measurement + Persistence + Stop/ Escalation per selected Scope.

**Drill:** Consume previous **accepted** card state and unresolved semantic obligations. Favor UPDATE to tighten target, measuring method, causal boundary, constraints and knowledge links. Reuse same card where possible. Each update must identify a material semantic gain compared with the prior batch. Preserve rejected/unknown claims and the original whole-task denominator.

**Mechanical paging:** Existing `scripts/card_delta.py` accepts `batch_size=4` without code changes. CLI's cursor belongs only to **one immutable Before/After** pair. New semantic Drill changes create a new delta cycle; do not reuse earlier cursor. Host owns every computed field, identifier, digest, path, numeric measure and command; cards and prompts never fabricate them.

## 5. Semantic Scope → Inner Prompt Delta bullet contract

For each admitted atom, supply to the inner worker:

- **Goal outcome:** The user-observable result this atom contributes toward, and the parent goal that stays open if unmet.
- **Required behavior:** The specific change in observable behavior, not pre-selected implementation steps.
- **Constraints & exclusions:** Legal owner/write/effect boundary, invariant and counterexample to avoid.
- **Measurement & acceptance:** What independent producer/metric/test oracle will decide success, including sample applicability; do not invent results.
- **Evidence & causal hypothesis:** Only facts and supported premises the worker needs; retain unresolved questions.
- **Stopping and return:** Writer-scoped completed, blocked or failed outcomes; report later publication/native/goal measurement obligations to Soodles outer loop.
- **Freedom:** Inside the admitted boundary and selected Poteto playbook, engineer may choose code, algorithm and sequence without asking the outer loop to specify the steps.

No Digest, SHA, generated ID, Cursor, Git HEAD, timestamp, token budget estimate, absolute path or executable argv is authored by a model in a Card or Prompt Delta. The original Host materializes any mandatory machine fields.

## 6. Continuation and completion

1. `CONTINUE`: semantic Drill has more justified work or frozen delta has further Host-owned page; original whole-task goal persists.
2. `DONE`: the current knowledge compilation pass and relevant immutable delta pages are exhausted; **not** that the product goal or all atoms are completed.
3. `BLOCKED`: required source/metric/owner readback/capability or non-card reconciliation prevents dependent progress; preserve unaffected work and a named missing input.
4. `NOOP`: no meaningful source/semantic change; do not invent another card or model critique.
5. Goal attainment is evaluated **outside knowledge compile**: original metric producer and owner provide actual observed success over the agreed population, Test Manager verifies necessary controls, Schema Manager records consumption, then original lifecycle/delivery owner applies existing terminal gates.
6. When measurements remain below goal, select a **new bounded causal atom** only on evidence of a new hypothesis or unresolved work; preserve the same parent REQ, history, constraints and effort policy. Do not reset budgets by generating another Issue.
7. Treat repeated identical failed attempts, exceeded budgets, unavailable provider access and unknown effects as reasons for evidence-oriented reassessment or bounded halt, not as permission to run indefinitely.

## 7. Complete example: p95 CI improvement

The following is **illustrative semantics**, not a measured result or an assumption that BigQuery is connected.

### Parent goal (retained across atoms)

- **Goal:** Keep the measured p95 CI duration below 10 minutes for the agreed relevant workflows/population.
- **Measurement:** If a real BigQuery CI-run table is available, use its owner-validated query and agreed duration boundaries, sample population, observation period and exclusions. If not, identify the real provider and measurement gap; do **not** fabricate rows, table names, SQL, elapsed times or a pass result.
- **Persistence:** Continue with evidence-driven, bounded interventions under the same original goal after each completed atom. A multi-week improvement campaign needs real authorized host continuation/scheduling and cost permissions; it is not a self-running model promise.
- **Stop / Escalation:** Close the parent goal only with actual accepted owner measurements over the agreed population and delivery checks. Reassess cause after repeated failed corrections or inconclusive comparisons; return a named missing owner input or budget decision without spinning a new issue.

### Proposed Behavior Scope: remove one *observed* redundant CI build

- **Kind:** `implementation`.
- **Causal claim:** An identified duplicate build/fixture step adds avoidable latency. This is a **hypothesis** until verified by real logs and controls.
- **Atom acceptance:** Within selected CI scope, remove a demonstrably redundant rebuild while preserving the necessary equivalent outputs, inputs, and behavior controls. Compare suitable measurements before and after using the original metric producer.
- **Required card composition:** CI-run duration definition (Concept), unnecessary rebuild evidence (Detail/Verification), no-loss build artifact requirement (REQ/SPEC), reusable rollback/safety constraints (G), negative control for changed dependency (V), and measurement unknowns (K) when applicable.
- **Outer Route:** Always start with original Session's `issue-atom` preparation and effective admission. If evidence already demonstrates the duplicate, **no extra think**; Test Manager selects minimal controls. If true cause is unknown, trace existing logs; if competing interventions confound improvements, route `ablation` and ask Test Manager for matched observation. Only after an actual candidate readback, route `outer-review` if unnecessary complexity/diff risk needs investigation. No Cron/Hook unless the existing native owner requires them.
- **Inner task (semantic Prompt Delta bullets):**
  - Eliminate only the evidenced duplicate CI work within the admitted boundaries.
  - Preserve the original build output contracts, artifact availability and failure reporting.
  - Choose the implementation technique and local work sequence independently through the already selected Poteto mode.
  - Exercise exactly the Test Manager-selected controls and retain genuine negative cases.
  - Report writer completion or named blocked evidence; do not claim the parent p95 objective or provider delivery.
- **Owner follow-up:** Soodles consumes writer result and appropriate actual provider measurement, exact-head checks and landing readback. If the parent p95 goal is not yet demonstrated, preserve it and choose the next bounded atom only from a new actual finding.

### Proposed Behavior Scope: measurement meaning unresolved

- **Kind:** `decision` or `evaluation`, not a code-implementation atom.
- **Unresolved:** Is p95 calculated from queue-start to terminal run, or only running job time? Which workflow runs matter?
- **Outer Route:** Inspect present workflow definitions/data dictionary first. If the two interpretations produce a genuine product choice, use `thinking-router` → installed `grilling` to settle the required success definition; `think` is only needed for an architecture recommendation, not the user-owned threshold. If the product goal is settled but a model-judged quality outcome lacks a failure taxonomy, use applicable installed Evals skills and actual traces; do not route numerical p95 into an LLM judge.
- **Inner Task:** No worker implementation until the measurement boundary can produce an authorized Issue Contract. Independent source/evidence collection may continue.

## 8. Focused acceptance controls for this profile

- Four visible slots, no fabricated filler; terminal partial batch uses `UNUSED`.
- One Scope with six relevant cards yields one causally bounded proposed Atom; no enforced Card→Issue mapping.
- Every Scope contains Goal, Measurement, Persistence, Stop/Escalation, local causal boundary and whole-task link; all may be `UNRESOLVED` **only with named missing source/decision and responsible next route**.
- Architecture ambiguity selects `think`; goal tradeoff selects `grilling`; eval validity with available traces selects installed Evals; objective p95 calculation selects measurement producer—not a judge.
- Clear original next produces no extra thinking route, dual-brain review or Prompt Delta.
- Worker can choose implementation details but cannot expand authorized scope or claim later delivery.
- New semantic Drill updates create a fresh delta cycle; old cursor is not reused; unchanged cards are not revised.
- Native Hook/Cron, real future scheduling and actual p95 success require source/owner measurements, not model forecasts.
- No unrecognized fields appear in legacy knowledge-record JSON; optional `extension_fields` stay in proposed sidecar until registered and validated.
